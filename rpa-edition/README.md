# 旅游运营助手 RPA 版

独立的 Electron 程序，和仓库根目录的接口版互不依赖。所有群消息都通过本机（或局域网执行端）已登录的企业微信 / 微信桌面客户端发出，**不调用任何企业微信官方接口**（没有 `@wecom/cli`，不请求 qyapi.weixin.qq.com），不需要企业微信管理后台权限。适合账号挂在别的企业下（例如携程）、进不了管理后台的情况。

## 构建和运行

需要 Windows x64 和 Node.js 18+，在本目录下执行：

```powershell
cd rpa-edition
npm install
npm run typecheck
npm run dev      # 开发运行
npm run build    # 生成 dist\TravelBot-RPA-Setup-<版本>.exe
```

安装后的程序名为 TravelBotRPA，数据保存在自己的用户数据目录，和接口版分开。

## 怎么用

一个群对应一个旅游团。客户只录三样东西，软件按团的出行日期每天傍晚自动组织内容并发送，团结束后自动停发。内容（行程、酒店介绍、景点攻略和图片）都是客户自己录的，软件只负责组织和发送。数据存在本机的 SQLite 里。

| 录什么 | 在哪里 | 内容 |
| --- | --- | --- |
| 路线 | 素材库 → 路线 | 路线名；每天一行：城市（查天气）、当天行程、当晚酒店、要发的景点攻略。可以从 Excel 贴入（第几天、城市、行程、酒店、景点） |
| 酒店、景点 | 素材库 → 酒店和景点 | 酒店的介绍和周边TIPS；景点的一句话攻略和攻略图 |
| 团 | 群管理 → 新增团 | 群名（和企业微信里一致）、出发日期、路线、发送账号。天数跟路线走，不填结束日期；可以按天换酒店 |
| 模板 | 内容中心 | 明日提醒、酒店TIPS、景点攻略、行程总览、酒店明细五个模板，和天气对照表 |

团的状态按日期自动算：待出发 → 进行中 → 已结束。以 10 月 12 日出发的 6 天团为例：

- 10 月 11 日（出发前一天）傍晚：行程总览、酒店明细、第 1 天的明日提醒和景点攻略。
- 10 月 12 日到 16 日每天傍晚：明日提醒（明天的天气、出行必备、行程、建议着装）、今晚酒店的TIPS、明天的景点攻略（一个景点一条，附攻略图）。
- 10 月 17 日（最后一天）起不再发，群留在列表里显示“已结束”。

出行必备和建议着装查天气对照表：明天的天气命中哪几行就合起来、去掉重复。天气查不到时去掉“天气参考…”半句，只用“每天都带”那几行。

其他：

- 首页列出今晚每个群要发的内容，点开能看完整文字（实时查天气），不对可以跳过这个群；也能“发到文件传输助手试看”。
- 发送计划：自动排出的每一组，只看、跳过、重发，不手动建任务。一组里某条失败，5 分钟后只重发没发出去的，最多 3 轮。
- 群详情里可以暂停、取消团，改出发日期或路线后还没发的自动重排，已发的不重发；也可以“临时发一条”（比如拼团通知），同样走防封规则。
- 设置里可以改每天傍晚开始发送的时间（默认 15:00）、开机自动启动，以及导出备份 / 从备份恢复。
- 旧版本的“运营任务、内容审核、行程提醒、每日推送”已经去掉；旧路线的行程节点会自动转成按天排的日程。

## 云南示例数据（测试用）

素材库 → 酒店和景点 → “导入云南示例数据”：导入昆明、大理、丽江等地的景点攻略（带示意图）、酒店，以及一条“云南昆明大理丽江6日游”。导入时可以选择再建一个测试团：群是自己的“文件传输助手”，明天出发，从今天傍晚起每天把这个团的消息发到文件传输助手，不会发到任何客户群。

图片都是程序画的示意图，不是实景照片；用 `python3 scripts/make-sample-data.py` 重新生成（`--tour-only` 只更新路线和酒店，不重画图）。

## 怎么发出去

程序自动操作已登录的客户端：切到前台 → 搜索快捷键（默认 Ctrl+F）→ 粘贴群名 → ↓ 选中第一个结果 → 回车进群 → 核对群名 → 粘贴文字 → 逐张粘贴图片 → 发送键。

- 每次按键前都会确认前台仍是客户端窗口，被切走就停止；多个任务同时到点会排队执行；结束后恢复剪贴板。
- 发送前核对群名（默认开）：进群后用 Windows 自带 OCR 识别聊天窗口标题，和群名对不上就不发，记为失败。如果群名还留在搜索框里，说明没进到群，也会停止、不粘贴。需要系统装有中文“光学字符识别”语言功能（“检测本机客户端”会提示）；识别截图保存在数据目录的 `rpa\chat-title.png`。
- 发送成功后把客户端最小化，切回发送前的窗口（默认开，可在设置里关）。弹出安全验证时不收起，方便扫码。
- 可选“只粘贴，人工按发送”，用于试跑。
- 限制：电脑不能锁屏，发送时会占用屏幕和剪贴板几秒钟。

## 防封

防封规则内置、不能在界面里调整或关闭（旧版本保存的自定义值不再生效）；只有发送时段和每条附图张数（0–3）可以改。一个团一晚的一组消息算一次发送。

- 每步操作随机停顿；同一组里条与条之间随机 3–8 秒；群与群之间随机间隔 60–180 秒；图片之间随机 2.5–6 秒。
- 每小时 / 每天 / 单群每天限次 10 / 40 / 3（按组算）。按每小时 10 组，30 个群大约 3 小时发完。“文件传输助手”不是群，不受单群每天限次（用来测试），但计入每小时、每天的总数。
- 只在发送时段内发（默认 07:30–21:30）。傍晚开始时间要在时段内；当天没发出去的不再补发，发送计划里显示“已错过”。
- 连续失败 3 次暂停 30 分钟。
- 安全验证检测：发送前和发完后用 OCR 检查客户端有没有弹出“安全验证 / 设备环境异常”。弹出就暂停这个账号的全部发送，并弹系统通知（验证有时限，超时会被退出登录）。发完才弹出的，这条算已发送、不重发。扫码验证后到“设置”点“检测本机客户端”，没有弹窗就恢复发送。
- 提醒邮件：在“设置 → 提醒邮件”填 SMTP（腾讯企业邮 smtp.exmail.qq.com:465、QQ 邮箱 smtp.qq.com:465 等）、发件邮箱、授权码和收件人，弹出安全验证时会发邮件。授权码用 Windows DPAPI 加密保存；可以先点“发测试邮件”。每台电脑（主控、执行端）各自配置。
- 风控无法完全避免：模拟按键能被客户端识别。建议用一台专用的实体电脑长期登录（虚拟机可能被判为环境异常），发送时不开远程控制、录屏、抓包工具，也不要有人操作这台电脑；新账号前一两周少发。

## 账号池（多台电脑）

企业微信一个账号只能稳定登录一台电脑，多个账号就用多台电脑、一台一个账号。

- 一台设为“主控”，管路线、素材、模板和团。其他电脑装好本程序，在“设置 → 本机角色”选“执行端”，把显示的 IP、端口（默认 47820）和配对口令填到主控的“账号池”里。
- 群管理里给每个团选“发送账号”（比如每个管家用自己的企业微信），没选的用第一个可用账号。主控把发送指令和图片通过局域网交给对应执行端，执行端用本机客户端发。
- 防封限频、群间隔和熔断由每台执行端按自己的账号计算；发送时段以主控为准。
- 主控和执行端需在同一局域网，第一次启动执行端时 Windows 防火墙会询问，选“允许”。
